## 传播结构 Hard Gate
- 目标不是“解释作品”，而是让外部观众看完后愿意**转发、收藏、复刻**或继续调用当前 Skill。
- `reproduction_prompt` 是可复制的短入口，**不是完整生图 Prompt**；本项目默认 Skill 名为 `couple-photo-orchestrator`。
- CTA 句式必须动态变化，不能机械复读同一句。
- `复刻提示词` 是强制可见标题，**不得省略标题**后直接裸放调用句。
- 每一个标签都必须以 `#` 开头，并**用空格分隔**；例如 `#杭州情侣照 #曲院风荷 #江南雨景`。禁止写 `标签：杭州情侣照、曲院风荷`。
- `story_card_name` 是强制可见短标题，必须显示成 `《{{story_card_name}}》`，不得只留在内部状态或“抽中主题”字段。
- 固定结构：`【分享文案】` → `《短标题》` → 1–2 句传播钩子 → 独立标题 `复刻提示词` + 可复制调用句 → 4–7 个逐个带 `#` 的 Hashtag → 1 句对外 CTA。
- `复刻提示词` 标题不得省略；调用句必须以 `@{{current_skill_name}}` 开头。
- `share_hashtags` 每个标签必须以 `#` 开头并用空格分隔，禁止 `标签：A、B、C` 或无 `#` 关键词串。
- CTA 必须面向外部读者，是自然的社交邀请；禁止 `下一次可以… / 你可以只改… / 保留这对情侣 / 保留关系动态 / 下一轮… / 继续执行…` 等内部操作说明。
- 可以借用 Remix 思路，但要改写成传播句，例如：`把“洱海”换成你们的下一站，看看同样的默契会落进什么风景。`
- 禁止暴露：`新卡已生成`、`抽卡结果`、`当前处于抽卡模式`、`切换回自主模式`、`项目校验`、`VALID`、内部文件路径、deliverables、schema、测试状态。

- **渲染前编译 Hard Gate**：Share Card 必须在图片生成调用之前完成并缓存；默认先向用户展示 Share Card，再触发图片工具。不要依赖图片完成后追加文案。
