# 项目交互与输出规则 (Project Interaction & Output Rules)

## 风格录入与特征提取铁律（严禁提取示意图具体画面内容）
- **严禁将参考图/示意图的具体画面内容提取为风格特征**：
  - 无论通过任何 Skill（如 `style-library-importer`、`tweet-style-importer` 等）或直接操作新增/录入画风或摄影风格时，**绝对禁止**将参考图、示例图、推文配图中的具体画面内容（包括主体人物、性别外貌、服装穿搭、动作姿势、具体动植物、道具、具体场景建筑与情节叙事）写入风格特征（traits）。
  - **严禁出现的违规特征反例**：“白色棉麻长裙的年轻女性”、“黑色短发”、“侧身回眸”、“大面积黄色花田”、“湖海远山”、“咖啡杯”、“雨伞”等。
  - **特征描述只允许包含纯粹的艺术视觉语言**：
    1. 媒介与材质（如钢笔线描、水墨晕染、胶片颗粒、油画肌理、矢量平涂）；
    2. 色彩倾向与光影质感（如高饱和通透、日系青蓝冷调、暖调复古、侧逆光光晕）；
    3. 空间与景深机制（如浅景深大光圈虚化、平铺留白、空气感、极简构图）。
  - **主题解耦原则**：画风特征必须对任意后续主题（如“宇航员在月球”、“老人在雨中散步”、“猫咪在厨房”）完全透明无侵入。画面中的一切主体、服饰与环境必须 100% 由用户输入的画面主题（Theme）定义。

## 画廊首页链接追加规范
- 输出传送门前，优先定位本次实际加载的手绘风格 Skill 的 `SKILL.md`，取同目录的 `gallery/index.html`。从项目根目录运行时可用根目录下的 `skills/handdraw-style-prompter/gallery/index.html`。确认文件存在后，用 Python `Path(实际文件路径).resolve().as_uri()` 生成 URL，并替换下方链接目标。在 Codex 中使用 `open_in_codex` 和 `target.type="browser"` 打开生成的 URI。聊天中的本地 Markdown 链接会进入文件预览，因此传送门指向已打开或已请求打开的 Browser 标签。
- 无论回答任何问题、执行任何操作或交付任何成果，在每次对用户的回复末尾，都必须固定追加以下画廊入口说明（包含分割线）：

---
🎨 **画廊传送门**：手绘风格画廊首页（Codex Browser 标签）

## 出图后的社区分享入口
- 本项目任何 Skill 开始处理创作请求时，在解析主题和编译提示词之前，逐字保存用户最初的创作消息正文；不要以解析后提示词代替，也不要收集整段对话、环境上下文或账号密钥。
- 分享时保留原始提示词不变，仅在末尾附 `【画风：FA-013 】` 这样的实际编号标签；只有实际使用图型时才附 `【图型：IG-038 】`，多个编号用顿号分隔。不写备注标题、编号说明、“未使用”或“未记录”等空字段，不恢复二阶段参数或完整展开提示词。原生资产关联仍单独通过 API 传递。
- 成功交付生成图片后，按安装包根目录下 `skills/community-share/references/conversation-sharing.md` 准备本地分享草稿，并在回复中附上“分享到网站”入口；一批图片对应一个入口。
- 此分享入口的目标是网站“作品广场”。使用 `/studio/api/entries` 创建 `kind=work` 的免费作品，并通过 `assets` 正式关联画风和图型；不能直接用论坛 `/posts.json` 发帖代替，也不能把论坛帖链接当成广场作品链接。
- Codex / Claude 本地客户端均输出脚本返回的标准 Markdown 分享链接，打开本机预览页；页面内提供真实的“分享到作品广场”按钮。不得把 `:codex-followup` 等宿主未渲染的指令声称为可点击按钮。无法运行本地服务时，明确使用“回复分享到网站”的文字触发。
- 准备草稿、打开预览页均不上传、不发帖；用户点击页面内发布按钮或明确回复“分享到网站”后才发布该草稿中的图片与原始指令。成功后返回真实帖子链接，重复点击不得重复发帖。
- 入口置于成果说明之后、画廊传送门之前。仅提示词、参考图或生成失败时不提供分享入口。
