# 排字细节（正文字体、标点混排、横向压缩、图层顺序、对照测量）

这些规则来自对一个参照账号做的 5 篇 1:1 复刻练习：用 Vision OCR 加颜色阈值把她每一行字的墨迹框量出来，再用候选字体反解字号、字距、横向缩放，几何误差压到 1440 宽的 1% 以内。下面是能迁移到 AI 线的部分。已定的视觉规则不变：毛笔双色标题、电子青强调、暗底 `#080808`、位图放大 ≤1.25、不拉伸、不 AI 换脸或补画。

## 1. 正文字体按题材选

参照账号每篇都换正文字体：两篇用仿宋系（华文仿宋，加粗、略拉宽），一篇宋体-简 Regular，一篇霞鹜文楷 Medium（横向 0.90），一篇苹方 Light（横向 0.953）。标题字体反而稳定。

`手排.BODY_FONTS`：

| 名字 | render 字体 key | 来源 | 适合 |
|---|---|---|---|
| 宋体粗（默认） | `serif-bold` | assets/fonts 思源宋体 700 ＋ 1px 描边 | ELIZA 以来的默认正文，什么都能用 |
| 宋体 | `songti-sc` | 系统 宋体-简 Regular | 旧报纸、文史、书页感 |
| 仿宋 | `fangsong` | 系统 华文仿宋（系统字体资源） | 档案、公文、实验记录 |
| 楷体 | `kaiti` | 系统 楷体-简 Regular | 书信、手记、人物自述 |
| 文楷 | `wenkai` | 霞鹜文楷 Medium（OFL），要自己放进 `assets/fonts/LXGWWenKai-Medium.ttf` 或 `~/Library/Fonts/` | 温和的讲故事口吻 |
| 苹方细 | `pingfang-light` | 系统 苹方 Light | 产品、界面、现代科技 |

找不到字库会直接报错（不静默回退）。做法：

```python
S.font_sample('冯·奥斯滕说——它会算 12+7……【真的】', '同字对比小样.png', typo=True, hscale=0.95, size=56)
```

一张图里每款字体排同一句话，看完选一款，整篇正文只用这一款。描边加粗默认：宋体粗 1px，其他 0（浅字压暗底时可以试 `stroke=1`）。

## 2. 标点与混排（`typo=True`）

参数在 `render.TYPO`，单位 em（= 字号）：

| 规则 | 实现 | 数值 |
|---|---|---|
| 破折号「——」 | 每个「—」画一段细线，两字之间留一道小缝，成为两段带间隙的细线 | 线长 0.74em，粗 0.045em（＋描边），每字推进 0.86em，竖直居汉字字面中线 |
| 省略号「……」 | 每个「…」画三个圆点，推进 1em，点距 1/3em，所以「……」六点等距 | 点径 0.12em |
| 【】 | 推进 0.44em，【 墨迹靠右、】墨迹靠左，留 0.03em | — |
| 间隔号「·」 | 推进 0.30em，墨迹居中 | — |
| 数字、拉丁字母 | 换 Times New Roman（`serif-latin`；找不到时回退随包 Noto Serif SC 并给 RuntimeWarning，不报错），放大 `latin_scale`（默认 1.07，建议 1.05–1.10），共用基线 | 参照账号的西文普遍比汉字同号大 5–10% |

这些图形字最多悬挂 0.6 字，超出就换行。毛笔标题的标点间距检查（≤0.2em）不管这几个字，它们有自己的间距。

`tight`：宋体粗默认按墨迹收紧标点（原样）；换别的字体默认 `tight=False`，用字库自带的全角标点，收紧后的冒号、逗号在仿宋、楷体里会像半角。

## 3. 两端对齐（`justify=True`）

- 断行改成「满行」：按词（jieba 和 protect 词）往行里塞，塞不下才换行；「12+7」「GPT-4o」这种连续西文不拆，开引号和「【」不留行尾。T.wrap 的分句断行行尾参差大，硬拉会出大窟窿。
- 段末行（含手动换行 `\n` 前的行）不拉。
- 参照账号的两端对齐字距增量肉眼几乎看不出，所以上限很紧：
  - 含空格的行只拉空格（参照账号就是这样），每个空格最多加 0.5em；超过就改成均分到字间。
  - 字间均分时每个缝最多加 0.05em，超过就整行左对齐、不拉。
  - 相邻两个西文字符之间不加，标点两侧不加（守住标点间距），破折号、省略号内部不加。
- 标点挤压：断行时下一个字（或「12+7」这种不拆的词）差一点放不下，先把行内全角标点（，。、：；！？「」（）“”《》【】等）最多压到半宽来腾地方，放得下就不换行；开引号类压缩时字形左移。只在 justify 且没开墨迹收紧（tight）时生效。

## 4. 横向压缩（`hscale`）

`body/headline/big(..., hscale=0.95)`：先在宽 `w/hscale` 的框里排好，再把整块文字横向缩到 `hscale`，左边 x 不动，所以断行按压缩后的真实宽度算。审计（render-report 的墨迹框、字形框）同步换算，`check_all` 和手绘圈照常能用。参照账号正文约 0.95，标题一般不压。只压文字，图片不受影响。

## 5. 图层顺序

默认：底色 → 整页底图 → 拼贴（卡片和它的柔影一起）→ 文字。

参照账号很多页是「底色 → 投影 → 文字 → 图片」：图片压住文字边缘，投影在文字下面，所以字不会被投影压暗。做法：

```python
cv = S.Canvas(split_shadow=True)        # 卡片柔影单独存 Pxx_shadow.png
...
S.pages.append(S.page(cv.save('P05'), [h, b1, b2], layer_order='text-under-images'))
```

render 里标了 `above_text` 的图片在文字之后画。没用这个选项的页面与原来逐像素相同。图片压字时注意别把关键字盖掉，压边缘、压最后半行就够。

## 6. emoji

PIL 画不全组合 emoji（1️⃣ 是「1 + FE0F + 20E3」三个码位）。`S.emoji('1️⃣', 64)` 调 `scripts/emoji.swift`（AppKit，Apple Color Emoji，首次自动编译到 `bin/emoji`），2 倍超采样后缩回，按墨迹裁边，高度约等于字号。拿到的是透明 RGBA，用 `Canvas.put` 摆在行首，竖直对齐到这一行的行高中间。

## 7. 对照测量（`scripts/对照.py`）

```bash
python3 scripts/对照.py 参照/p03.jpg pages/p03.png --json 偏差.json
```

- 两张图都换算到 1440 宽坐标；并排图同高，参照在左（绿框），我们在右（紫框，超差标红），框上编号对应偏差表的行号。
- 行框：`ocr.swift`（简体中文优先）找行，再在行框附近按颜色类（white/yellow/orange/cyan/red；浅底上 dark）量墨迹外接框，取与 OCR 框中线重叠最多的一段。
- 配对：默认按文字相似度（≥0.5）；文案不同只比版式时用 `--match order`。
- 偏差 = 我们 − 参照：Δ左/Δ上/Δ右/Δ下和字高（墨迹高 ≈ 字号）、字高比；超 `--tol`（默认 1% = 14.4px）标出。
- 常见假象：首字太细被阈值漏掉、行框连进图片亮部、贴条亮边混进字。看并排图确认，不要为了数字去挪对的字。
- 字号反求：同一块各行「参照墨迹高 ÷ 我们墨迹高」取中位数乘到字号上；字距看宽度残差。

参照图只在本机处理，不上传到任何外部网站。

## 8. iCloud

工程在 iCloud 同步目录里时，磁盘紧张会把文件清成占位（读取卡死）。先 `brctl download <路径>`；长任务把工程复制到本地临时目录跑，跑完同步回来。
