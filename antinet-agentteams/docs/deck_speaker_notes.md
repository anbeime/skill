# 技术方案 Deck · 逐页 Speaker Notes

> GOAI 赛道一（Agent Infra 新智基座）— 面向复杂知识任务的多智能体基础设施（材料文献调研为可运行示例场景）
> 篇幅分配遵循赛道一评审权重：场景价值 25% + 多 Agent 协同 25% + Skill 体系 25% + 工程落地 20% + 开源 5%

---

## P1 · 封面
- **标题**：基于八官署多智能体架构的材料文献科学发现智能体
- **副标题**：GOAI 赛道一 · Agent Infra（新智基座）
- **演讲要点**：一句话定位——把「明朝内阁」治理体系映射为多智能体协作框架，文档进、四色卡片出、知识回流回库。强调三个关键词：可审计、可复现、有科学意义。

## P2 · 科学问题（科学意义 30%）
- **痛点**：材料文献爆炸式增长，研究者难以系统性识别 (1) 文献间矛盾 (2) 研究空白 (3) 早期结论被后期证伪的「时间张力」。
- **SnSe 实例**：Se 空位形成能理论预测 -0.2eV（稳定）vs 实验 >5% 即相分离——认知冲突真实存在，但 Manual 调研极易遗漏。
- **演讲要点**：本项目的科学问题不是「再训一个大模型」，而是「如何让文献调研过程可检查、可延续、可证伪」。

## P3 · 为什么多智能体（方法创新 20%）
- 单 Agent 把检索/解析/抽取/核验/假说全搅在一起，是参赛者「一周大半时间修 Docker」的根因。
- 八官署职责隔离、上下文不互相污染，正是材料计算领域推荐的多智能体架构。
- **演讲要点**：多智能体不是炫技，而是让每个环节可被独立验证、独立降级。

## P4 · 八官署架构总览
- 指挥使（编排）/ 锦衣卫（安检）/ 密卷房（解析）/ 通政司（蓝卡）/ 监察院（绿卡）/ 丞相府（红卡）/ 军机处（核验）/ 太史阁（记忆）。
- **演讲要点**：职责边界清晰，任一官署失败由指挥使熔断降级而非整系统崩溃。

## P5 · 八官署 → 材料 Agent 映射
- 文献检索+OA下载 → 通政司+军机处
- PDF解析（MinerU三级fallback）→ 密卷房
- 防假全文冒充 → 锦衣卫
- 抽取+标出处+找Gap → 通政司(蓝)+监察院(绿)
- 构效假说+行动 → 丞相府(红)
- 日志/向量/沉淀 → 太史阁
- **演讲要点**：每个赛题硬要求都有明确官署承接，链路无断点。

## P6 · 主链路时序
- 指挥使接收主题 → 锦衣卫扫描 → 密卷房解析 → 通政司蓝卡 → 监察院绿卡 → 丞相府红卡 → 军机处MP核验 → 太史阁provenance。
- **演讲要点**：太史阁在任务前先检索历史沉淀（读库再干活），任务后回流（产出回库）——这是知识复利的关键。

## P7 · 四色卡片数据模型（方法创新）
- 蓝卡：可验证事实（quote + paper_id + location + parser）
- 绿卡：因果/Gap（必 cite 蓝卡，gap_type 三选一）
- 黄卡：合规/风险（risk_level + 触发规则）
- 红卡：可执行下一步（owner + due + accept_criteria，必 cite 绿/蓝卡）
- **演讲要点**：四色卡片比纯 Markdown 报告更契合 GOAI「可检查信号」的评审口味，且天然满足「每条结论点回原文」。

## P8 · SnSe 蓝卡示例
- 展示 `examples/snse_survey/blue_cards.json` 中 7 张蓝卡。
- 重点：每张都带 `paper_id` 与 `location`，评委可逐条回原文核验。

## P9 · SnSe 绿卡（Gap）示例
- 展示 6 张绿卡，覆盖 contradiction（Se空位形成能矛盾）、underexplored（Sn空位研究空白）、temporal_tension（早期DFT高估稳定性）。
- **演讲要点**：Gap 类型化是「科学意义」的直接体现，而非堆砌摘要。

## P10 · SnSe 红卡（构效假说）示例
- 3 张红卡：Sn空位提升ZT、Se空位稳定窗口、空位有序相低温稳定。
- 每张含「下一步验证 + 证伪实验设计」——这是科学发现闭环的核心。

## P11 · 可复现性（技术性能 45%）
- `docker compose up -d grobid qdrant` 一键起解析/检索依赖。
- `python scripts/verify_production.py` 输出标准化 JSON，退出码 0=PASS，可接入 CI。
- **演讲要点**：评委「点一下就能复现」远比 PPT 漂亮重要。

## P12 · 合规性（锦衣卫）
- Sci-Hub 等侵权源在 `production.yaml` 硬编码拦截。
- `no_local_cache_as_production: true` 防假全文冒充。
- 密钥扫描 + 数据不出域。
- **演讲要点**：合规不是附录，而是系统的一等公民（对应 GOAI 新智基座「可观测审计」精神）。

## P13 · 阶段性实验结果（技术性能）
- 论文 10 篇（全 OA），解析 7/10（过阈值 5/10）。
- 四色卡片：蓝8 / 绿7 / 黄0 / 红4（接入真实本地 NPU 后结果）。
- 溯源链路 traceability_ok = true。
- 验收 consistency = **PASS**。

## P14 · 诚实披露（降级现状）
- 解析：demo 用预存全文模拟 7/10；真实环境目标 ≥7/10。
- LLM 在环：✅ 已接入真实本地模型 genie:8910（llm_used=true），生成 3 张 LLM 卡片，如实标注。
- MP 核验：默认本地规则库降级，红卡标注来源与置信度。
- **演讲要点**：GOAI 最看重「理解问题、尊重证据、重视复现」，粉饰反而减分。

## P15 · 开源计划（开放开源 5%）
- 协议 Apache 2.0，仓库 `materials-agent/` 结构公开。
- 第三方依赖边界在 `DEPENDENCIES.md` 明示；闭源 LLM API 的调用接口与降级逻辑均开源。
- 数据集 OpenAlex（CC0）合法复用。

## P16 · 差异化亮点 vs 单 Agent
- 可审计性：太史阁全链路留痕 + 监察院合规检查。
- 四色卡片结构化：事实/解释/行动/风险分离，比纯文本报告可检查。
- 降级与容错：指挥使熔断 + 锦衣卫扫描，大模型挂掉/解析失败时不崩盘。
