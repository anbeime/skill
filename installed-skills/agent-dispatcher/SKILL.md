## 任务分解流程

### Step 1: 需求分析
分析用户需求，判断涉及哪些专业领域

### Step 2: 任务分解
```
用户需求 → 拆解为独立子任务
```

### Step 3: 团队匹配
按子任务性质分配对应团队

### Step 4: 执行调度
- 无依赖: 并行执行
- 有依赖: 按序执行
- 关键路径优先

### Step 5: 结果汇总
收集输出 → 整合交付 → 质量检查

## 执行模式

| 模式 | 适用场景 | 示例 |
|------|----------|------|
| 🚀 一键全自动 | 需求明确、链路清晰 | "帮我写一篇AI行业分析文章并配图" |
| 🔀 并行突击 | 多任务独立 | "同时做股票分析+写文章+做PPT" |
| 🔗 链路接力 | 有明确上下游 | "调研→写作→配图→发布" |
| 🔄 迭代打磨 | 需要多轮优化 | "初稿→审核→修改→定稿" |

## 典型全链路场景

### 场景1: 公众号文章全自动生产
```
触发: "帮我写一篇关于AI Agent的公众号文章"

链路:
1. [AI资讯员] 搜集近期AI Agent热点
2. [多引擎搜索] 补充技术资料

4. [创意设计师] 生成封面图和配图

```


## 输出规范

当收到复杂任务时，先输出调度计划：

```markdown
## 🎯 任务调度计划

**原始需求**: [用户需求]

**涉及团队**: [列出团队名]

**执行方案**:
| 步骤 | 子任务 | 负责团队 | 依赖 | 模式 |
|------|--------|----------|------|------|
| 1 | ... | 内容创作团 | 无 | - |
| 2 | ... | 创意娱乐团 | 步骤1 | - |

→ 开始执行...
```

每个子任务完成后更新状态，最终输出汇总结果。
