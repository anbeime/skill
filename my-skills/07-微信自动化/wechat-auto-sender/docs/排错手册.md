# 排错手册

排查任何问题前，先走一遍下面的**阶梯式自检**，90% 的问题都能定位：

| 步骤 | 命令 | 目的 |
| --- | --- | --- |
| 1 | `python scripts\send_daily.py --calibrate "目标名"` | 确认能打开正确聊天，并刷新标题参考图 |
| 2 | `python scripts\send_daily.py --dry-run` | 完整走流程但不发送，检查每一步命中位置 |
| 3 | `python scripts\send_daily.py --test` | 发到「文件传输助手」，验证端到端链路 |
| 4 | `python scripts\send_daily.py` | 正式运行 |

每次运行都会在 `logs/` 生成一个 `run_*.log`，**先看日志再看截图**。

---

## 一、微信相关

### 1. 微信没启动 / 停在登录界面

**日志特征**：`微信在运行但没有主窗口（可能停在登录界面）` 或 `微信停留在登录界面，需要人工用手机扫码登录`

**原因**：微信未登录，或登录二维码窗口尺寸较小（被识别为登录窗口）。

**处置**：手动扫码登录微信后重试。程序**不会**重复启动新实例，这是刻意设计——避免留下多个微信进程互相干扰。

### 2. 微信窗口在托盘里找不到

程序会扫描微信专有窗口类（`Qt51514QWindowIcon`），并对已隐藏的窗口调用显示指令唤醒，一般无需干预。
若确实找不到，先手动点开微信主窗口，再重试。

### 3. 出现「搜索聊天记录」等微信弹窗

程序会主动关闭这类微信自有弹窗（使用不依赖焦点的窗口消息），然后回到主窗口。
若关闭失败，多半是有其它窗口正在抢占焦点，见下一节。

---

## 二、窗口与焦点

### 4. 日志出现「前台已被其它程序抢走」

**原因**：程序准备点击/按键时，前台窗口不属于微信进程，出于安全立即中止。
常见诱因：输入法候选窗、聊天软件弹窗、下载完成提示、安全软件提示、你自己动了鼠标。

**处置**：关闭会抢焦点的软件后重试；运行期间不要使用鼠标键盘。

> 这是**保护机制而不是 bug**：宁可本次不发，也绝不把模拟点击丢到你正在用的程序里。

### 5. 日志出现「前台被微信的另一个大窗口占着」

**原因**：微信打开了另一个大窗口（如独立聊天窗口、图片查看器），挡住了主窗口。
此时窗口看起来正常，但所有点击都会落在错误的窗口上。

**处置**：程序会尝试把主窗口重新置前；若仍失败则中止并留现场。手动关掉那个多余窗口即可。

### 6. 提示锁屏放弃（返回码 3）

**原因**：Windows 会话锁定，桌面不可交互。

**处置**：关闭系统自动锁屏 / 屏幕保护，或把定时任务设为「只在用户登录时运行」。

---

## 三、搜索与打开聊天

### 7. 搜索框始终输不进文字

**日志特征**：反复出现 `第 N 次尝试：搜索框没吃进文字，重试`

**原因与处置**：

- 窗口刚被前置，最初的点击被系统吞掉 → 程序已内置「预热点击」与最多 4 次重试；
- 微信主窗口不是前台（见第 5 条）；
- 输入法处于特殊状态 → 切换一次输入法后重试；
- 坐标偏移 → 重新校准 `界面坐标`。

### 8. 标题一直校验不通过

**日志特征**：反复 `第 N 次尝试（click@Y）标题不符，换下一行`

**原因与处置**：

| 原因 | 处置 |
| --- | --- |
| 目标改过昵称 / 群名 / 头像 | 重新执行 `--calibrate` 生成新的标题参考图 |
| 搜索结果里该对象不在预期行 | 在配置里给该对象加 `结果行Y` 加速命中，或调整 `默认候选行Y` |
| 界面坐标偏移 | 重新校准 `标题裁剪区` |
| 阈值过严 | 可小幅调整 `标题相似度阈值`（**不要低于 0.8**） |

> 千万不要通过「关掉标题校验」来让程序跑通——那等于放弃了唯一的防错发闸门。

## 四、发送环节

### 9. 提示「输入框里检测到残留内容」

**原因**：微信聊天输入框里有未发送的草稿，程序检测到后中止，避免把旧内容一起发出去。

**处置**：手动清空该聊天输入框后重试。

### 10. 缺图跳过（本次不发送）

**日志特征**：`图片 xxx: 【缺失】` + `缺失 [...]，按配置「skip」跳过`

**处置**：把对应日期的图片放进 `图片文件夹`（文件名要符合 `文件名格式`），
或把 `缺图处理` 改为 `latest`（用文件夹里最新的一套补齐）。

### 11. 图片粘贴不进去

**原因**：剪贴板被其它程序占用，或图片文件损坏。

**处置**：关闭占用剪贴板的程序；确认图片能被系统看图软件正常打开。

## 五、定时任务

### 12. 定时任务没执行 / 执行了但没发出去

排查顺序：

1. 打开「任务计划程序」→ 查看该任务的**上次运行结果**；
2. 看项目根目录 `logs\` 下有没有对应时间的 `run_*.log`；
3. 看 `scripts\launcher.log`（启动器记录每次退出码，能区分「任务没跑」和「跑了但失败」）；
4. 确认任务「起始于」设置为项目根目录；
5. 确认运行时刻电脑**已登录且未锁屏**。

### 13. 提示找不到 Python

**日志特征**：`python runtime not found`

**处置**：把 `PY` 环境变量设为 `python.exe` 的完整路径，或确保 `python` 在系统 PATH 中。

## 六、日志与取证文件说明

| 路径 | 内容 |
| --- | --- |
| `logs/run_*.log` | 每次运行的完整过程日志（含每一步尝试与校验相似度） |
| `logs/shots/*_tryN.png` | 每次尝试打开聊天后的整窗截图 |
| `logs/shots/*_after.png` | 发送完成后的整窗截图 |
| `logs/shots/*_窗口.png` / `*_全屏.png` | 出错时保存的窗口截图与全屏截图 |
| `logs/shots/*_现场.txt` | 出错时的前后台窗口、微信所有窗口尺寸与标题 |
| `logs/state.json` | 当天已发送记录（用于去重） |
| `scripts/launcher.log` | 启动器每次运行的退出码 |

> 复盘时按「日志 → 现场截图 → 现场文本」的顺序看，基本能还原当时屏幕上发生了什么。

---

## 七、返回码

| 返回码 | 含义 | 常见处置 |
| --- | --- | --- |
| 0 | 成功（含「当天已发过，跳过」） | 无需处理 |
| 1 | 完成但有目标发送失败 | 按日志定位是哪个目标、哪一步失败 |
| 2 | 运行失败 | 看日志首行错误；多为配置错误或微信不可用 |
| 3 | 锁屏放弃 | 关闭自动锁屏后重试 |

---

## 八、仍无法解决？

收集以下三样，问题基本可以定位：

1. 最近一次失败对应的 `logs\run_*.log`；
2. 同一时间戳的 `logs\shots\*_现场.txt`；
3. 同一时间戳的 `logs\shots\*_窗口.png` 与 `*_全屏.png`。
