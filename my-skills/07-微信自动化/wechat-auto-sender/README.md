# 微信定时自动发送图片 · wechat-auto-sender

> 一个跑在 Windows 上的微信「定时发图」小机器人：每天到点自动把当天的图片
> （比如早安图、晚安图）发给指定的人或群，发完自动收工，全程不需要人盯着。

核心原则只有一句：**宁可这次不发，也绝不发错人、发错内容。**

## 它解决什么问题

做社群运营、门店客户维护的人，常常需要**每天固定时间**在微信里发一张图
（早安问候、晚安祝福、每日海报）。这件事本身很简单，但「每天都要记得做」很烦人。

这个程序把这件事自动化：

- 到点自动运行，无人值守；
- 支持一次发多个对象（多个群 / 多个联系人）；
- 每天可以发多张（按文件名区分「早安」「晚安」）；
- 发完自动把微信窗口还原，不打断你使用电脑；
- 出问题时留下现场截图，事后能查清楚到底发生了什么。

## 工作原理

程序**不破解、不注入、不读微信数据库**，而是像人一样操作已经登录好的微信客户端：

1. 通过窗口类名定位微信主窗口（微信 4.x 支持被隐藏到托盘，程序会把它唤醒）；
2. 把微信窗口临时移动到一个固定位置，让所有点击坐标保持稳定；
3. 在搜索框里粘贴目标对象的名称，点开搜索结果对应的聊天；
4. **比对聊天标题参考图**，确认打开的确实是目标对象；
5. 用剪贴板把图片粘贴进输入框，按回车发送；
6. 发完把窗口位置还原，并记录当天发送状态。

因为依赖界面坐标与截图比对，所以**换电脑、换分辨率、改微信窗口大小之后都必须重新校准**。

## 安全设计

这是本程序最值得关注的部分。所有「防呆」都做在了发送链路上：

| 机制 | 解决的问题 |
| --- | --- |
| **前台进程守卫** | 每次点击/按键前确认前台窗口属于微信进程；被别的程序抢走就立即中止，绝不让模拟点击落到你正在用的软件上 |
| **标题参考图校验** | 打开聊天后比对标题区截图；微信搜索结果行位置会漂移，程序会逐行点击、逐行比对，直到匹配为止，全程只认标题不认坐标 |
| **输入框空校验** | 发送前比对输入框截图，发现残留草稿就中止，避免把上次没发出去的内容一起发出去 |
| **多次尝试后放弃** | 所有候选方式都失败时中止该目标并记录，不做任何「猜一下」的点击 |
| **失败现场取证** | 出错时自动保存主窗口截图、全屏截图、前后台窗口信息文本 |
| **当天去重** | 记录每个对象当天已发送的类别，避免重复打扰，支持 `--force` 覆盖 |
| **锁屏检测** | 检测到 Windows 会话锁屏时直接放弃本次执行 |

> 这些校验会让程序的「成功率」看起来不如暴力点击高，但这是刻意的取舍：
> 一次误发到错误的群，代价远大于一次没发出去。

## 环境要求

| 项目 | 要求 |
| --- | --- |
| 操作系统 | Windows 10 / 11（依赖 Win32 API 与桌面会话） |
| 微信 | 桌面版微信 4.x，**运行前必须是已登录状态** |
| Python | 3.10 及以上 |
| 依赖库 | `pywin32`、`Pillow`（见 `requirements.txt`） |
| 其他 | 运行期间**不能锁屏**；不要在同一时间抢占鼠标键盘 |

## 安装

```powershell
# 1) 安装依赖
pip install -r requirements.txt

# 2) 生成配置文件
Copy-Item config.example.json config.json
```

然后按 [配置详解](#配置详解) 改好 `config.json`，再按 [坐标校准](#坐标校准换电脑必做) 生成参考图。

## 配置详解

`config.json` 每一项都有注释字段（以 `_` 开头的键是说明，程序会忽略）。
主要字段如下：

### 图片来源

| 字段 | 说明 |
| --- | --- |
| `图片文件夹` | 图片所在目录的绝对路径 |
| `文件名格式` | 文件名模板，例如 `{m}-{d}{kind}.jpg` → `9-18早安.jpg` |
| `发送类别` | 每天要发的类别列表，例如 `["早安", "晚安"]` |

### 发送对象

```json
"发送对象": [
  {
    "备注名": "示例群聊",
    "搜索关键词": "示例群聊",
    "标题参考图": "refs/示例群聊_title.png",
    "结果行Y": 131
  }
]
```

| 字段 | 说明 |
| --- | --- |
| `备注名` | 日志与状态记录里使用的名字 |
| `搜索关键词` | 在微信搜索框里输入的内容（填能唯一命中该对象的词） |
| `标题参考图` | 该对象聊天标题区的参考截图，由 `--calibrate` 生成 |
| `结果行Y` | 可选，搜索结果中该对象所在行的 Y 坐标（加速命中） |

`测试对象` 结构相同，供 `--test` 使用，建议保留「文件传输助手」。

### 运行时与坐标

| 字段 | 说明 |
| --- | --- |
| `微信程序` | `Weixin.exe` 的绝对路径 |
| `启动等待秒数` | 等待微信主窗口出现的最长时间（冷启动 + 自动登录可能 1–2 分钟） |
| `窗口位置` | 运行时把微信窗口移动到这里，发送完还原 |
| `界面坐标` | 搜索框、搜索结果第一条、聊天输入框、标题裁剪区、输入框裁剪区 |
| `默认候选行Y` | 搜索结果候选行的 Y 坐标列表，程序会逐行尝试 |

### 行为开关

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| `验证标题` | `true` | 是否启用标题校验（**强烈建议保持开启**） |
| `标题相似度阈值` | `0.88` | 越高越严格；调低会显著增加发错人的风险 |
| `输入框相似度阈值` | `0.8` | 输入框为空判定的阈值 |
| `日期口径` | `today` | `today` 用当天日期，`yesterday` 用前一天 |
| `缺图处理` | `skip` | `skip` 缺图跳过；`latest` 用文件夹里最新一套补齐 |
| `运行后恢复窗口` | `true` | 发送完成后把微信窗口移回原位 |
| `同一目标同一天只发一次` | `true` | 防止重复打扰 |
| `发送间隔毫秒` / `搜索等待毫秒` | `1800` / `2200` | 操作节流，别调得太小 |

## 坐标校准（换电脑必做）

程序的点击坐标是按「微信窗口被移动到固定位置、固定尺寸」为前提的。
换电脑、换分辨率或改窗口尺寸后，必须重新校准：

1. 启动程序跑一次 `--calibrate`，它会打开目标聊天并保存整窗截图与标题参考图；
2. 打开保存的整窗截图，对照它调整 `config.json` 里的 `界面坐标`；
3. 用 `--dry-run` 演练，确认每一步都命中正确位置（演练不会真的发送）；
4. 用 `--test` 发到「文件传输助手」做端到端验证。

```powershell
python scripts\send_daily.py --calibrate "示例群聊"
python scripts\send_daily.py --dry-run
python scripts\send_daily.py --test
```

## 日常使用

```powershell
python scripts\send_daily.py                # 正式发送
python scripts\send_daily.py --dry-run      # 演练，不发送
python scripts\send_daily.py --test         # 只发文件传输助手
python scripts\send_daily.py --date 9-18    # 指定日期
python scripts\send_daily.py --force        # 忽略当天已发记录
```

也可以直接双击 `scripts\run_send.cmd`（自动使用 `PY` 环境变量指定的解释器，未设置则用 PATH 中的 `python`）。

## 配置定时任务

用「任务计划程序」创建两个基本任务（例如每天 01:00 与 02:00）：

- **操作 → 程序或脚本**：`<项目目录>\scripts\run_send.cmd`
- **起始于**：`<项目目录>`
- **常规**：勾选「不管用户是否登录都要运行」时，注意程序需要**桌面会话**才能操作界面；
  如果电脑会锁屏，请把任务设置为「只在用户登录时运行」，并关闭自动锁屏。

> 提示：程序检测到锁屏会直接返回 3（放弃本次执行），不会做任何操作。

## 常见问题与排错

| 现象 | 可能原因与处置 |
| --- | --- |
| 搜索框输不进字 | 前台被微信的另一个大窗口占着，或窗口被抢占；确认运行期间不要操作鼠标键盘，必要时重启微信 |
| 提示「前台已被其它程序抢走」 | 有别的程序抢了前台焦点，程序按设计中止；关掉抢焦点的软件（如弹窗提示类工具）后重试 |
| 标题一直校验不通过 | 参考图过期（改过昵称/群名/头像）或坐标偏移；重新 `--calibrate` |
| 提示「输入框里检测到残留内容」 | 微信输入框里有草稿；手动清空后重试 |
| 提示锁屏放弃 | 关闭系统自动锁屏，或让任务只在登录且不锁屏时运行 |
| 微信没启动/停在登录界面 | 程序不会重复启动新实例（避免多开）；请手动完成扫码登录 |
| 发错对象 | 立即停止程序，检查参考图与阈值；**不要**通过调低阈值来「解决」问题 |

更多细节见 [`docs/排错手册.md`](docs/排错手册.md)。

## 返回码

| 返回码 | 含义 |
| --- | --- |
| 0 | 成功（含「当天已发过，跳过」） |
| 1 | 完成但有对象发送失败 |
| 2 | 运行失败（配置/微信/前置窗口等问题） |
| 3 | 锁屏，放弃本次执行 |

## 合规与风险提示

- 本程序只操作**你自己已登录**的微信客户端，不涉及协议破解、不读取微信数据；
- 请仅用于自己的账号与已获得授权的对象，**不要**用于骚扰、营销轰炸等用途；
- 自动化操作可能触发平台风控，请控制发送频率、避免短时间大量发送；
- 使用前请自行确认符合微信软件许可协议与相关法律法规的要求。
